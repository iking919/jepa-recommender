# Model Checkpoints

This directory stores trained model checkpoints generated by the experiment training pipelines.

Model weights are kept separate from experiment metrics and training history, which are stored under `results/`.

## Directory Structure

```text
checkpoints/
├── README.md
├── bert4rec_baseline/
│   └── bert4rec_baseline_best.pt
├── bert4rec_tuned/
│   └── bert4rec_tuned_best.pt
├── jepa_baseline/
│   └── jepa_baseline_best.pt
└── jepa_tuned/
    └── jepa_tuned_best.pt
```

## Checkpoint Naming

Each experiment has a dedicated directory:

| Directory | Model |
|---|---|
| `bert4rec_baseline/` | Baseline BERT4Rec |
| `bert4rec_tuned/` | Tuned BERT4Rec |
| `jepa_baseline/` | Baseline JEPA |
| `jepa_tuned/` | Tuned JEPA |

The `*_best.pt` checkpoint is intended to contain the model state selected during training based on validation performance.

## Checkpoint Selection

The training pipelines use validation performance for model selection. Where configured, the selected checkpoint is the one with the best validation NDCG@10.

Validation data is used for checkpoint selection; the held-out test set is reserved for final evaluation.

## Checkpoint Contents

Depending on the training pipeline, a checkpoint may contain:

- Model parameters
- Optimizer or scheduler state
- Epoch and validation information
- Experiment configuration
- Other state required to resume or evaluate training

Refer to the checkpoint-saving implementation for the exact fields saved by each model.

## Reproducing Checkpoints

Each checkpoint should correspond to an experiment configuration under `configs/`.

For example:

```text
configs/
└── bert4rec_tuned.yaml
        |
        v
checkpoints/
└── bert4rec_tuned/
    └── bert4rec_tuned_best.pt
        |
        v
scripts/
└── run_bert4rec_evaluation.py
```

The configuration defines the model architecture, dataset paths, and experiment parameters. The evaluation script loads the selected checkpoint and evaluates it on the held-out test data.

## Git Tracking

Trained checkpoint files are excluded from version control because they can be large and can be regenerated by running the training pipeline.

The repository retains the source code, configuration files, and documentation needed to reproduce the experiments.

If checkpoints are needed for a publication or release, distribute them through an appropriate external storage location and document the corresponding version and configuration.
