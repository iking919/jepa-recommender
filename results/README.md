# Experiment Results

This directory contains metrics, training histories, and run summaries generated by the BERT4Rec and JEPA experiment pipelines.

Model checkpoints are stored separately under `checkpoints/`.

## Directory Structure

```text
results/
├── README.md
├── bert4rec_baseline/
├── bert4rec_tuned/
├── jepa_baseline/
└── jepa_tuned/
```

Each directory corresponds to one experiment configuration.

## Experiment Directories

| Directory | Description |
|---|---|
| `bert4rec_baseline/` | Baseline BERT4Rec outputs |
| `bert4rec_tuned/` | Tuned BERT4Rec outputs |
| `jepa_baseline/` | Baseline JEPA outputs |
| `jepa_tuned/` | Tuned JEPA outputs |

## Result Files

Depending on the experiment pipeline, each directory may contain:

| File | Purpose |
|---|---|
| `training_history.csv` | Epoch-level loss, validation metrics, and timing |
| `run_summary.json` | Run configuration and summary information |
| `test_results.json` | Final held-out test metrics |

The exact files generated depend on the training and evaluation scripts.

## Evaluation Metrics

The project uses the following ranking metrics:

- **HR@5:** Hit Rate at 5.
- **HR@10:** Hit Rate at 10.
- **NDCG@5:** Normalized Discounted Cumulative Gain at 5.
- **NDCG@10:** Normalized Discounted Cumulative Gain at 10.

Metrics should be reported using consistent naming and precision across experiments.

## Validation and Test Results

Validation results are used to monitor training, compare configurations, and select model checkpoints.

Test results are computed on the held-out test set and should be used for final model comparisons. Test metrics should not be used to select model parameters or checkpoints.

Keep validation and test results clearly distinguished in reports, tables, and research writing.

## Training Performance

Where available, training histories record computational measurements such as:

- Training loss
- Validation metrics
- Training time per epoch
- Validation time per epoch
- Total epoch duration
- Peak GPU memory usage

These measurements support analysis of both recommendation quality and computational cost.

Training-time comparisons should identify the hardware, software environment, batch size, and number of epochs used.

## Reproducibility

Each result directory should be associated with the YAML configuration used to run the experiment and the corresponding checkpoint under `checkpoints/`.

For published results, record any deviations from the standard configuration, changes to the dataset, or differences in evaluation procedures.

Generated results are kept separate by experiment to avoid overwriting metrics from different model configurations.
